## #NEXO — ports from NexoIP 3D Viewer — ✅ ALL 4 SHIPPED 2026-08-26 (PR #58, `abbcbac`, deployed CT333)

Source: https://github.com/ikerperez12/NexoIP-3D-Viewer (MIT, © 2026 Iker Perez
/ NexoIP). An Electron desktop viewer — no architectural overlap with YASTL, but
its `src/utils/*.js` is framework-agnostic Three.js worth borrowing from.

Library composition as of 2026-08-26 (CT333): 1843 STL · 553 3MF · 27 STEP ·
11 GLB · 7 OBJ · 1 PLY · 0 FBX · 0 DAE. That ordering sets the priorities below.

| Mnemonic | Subject | Blocked by |
|---|---|---|
| NEXO-1 | Viewer render modes — wireframe / surface-normals / x-ray material swap, restorable without reloading the model. Applies to every model in the library, so this is the highest-value port. | — |
| NEXO-2 | PLY point-cloud detection — a PLY whose header declares no `element face` is a point cloud; YASTL currently wraps it in a `THREE.Mesh`, which renders nothing. Read the header, build `THREE.Points` instead, and carry vertex colors through the parse worker. | — |
| NEXO-3 | FBX + DAE viewer loaders. Both formats are advertised in `processor.py` `FORMAT_MAP`/`TRIMESH_SUPPORTED` but are broken end-to-end: trimesh has **no FBX loader at all**, and its `dae` loader needs `pycollada`, which is not installed on CT333 — so server-side GLB conversion fails, and the client then silently parses the file as STL. three.js's `FBXLoader`/`ColladaLoader` are the only working path. | — |
| NEXO-4 | `THIRD_PARTY_NOTICES.md` — YASTL has no `LICENSE` file, and MIT requires the copyright notice to travel with copied code. Credit the borrowed functions. | NEXO-1, NEXO-2, NEXO-3 |

An adversarial-review Workflow over the diff before shipping found 6 confirmed
defects (2 refuted), all fixed in the same commit — including one **pre-existing**
bug the render-mode dropdown made reachable: `applyClipToModel` set
`side = DoubleSide` on every material and never restored it. See memory
`nexoip-viewer-ports.md`.

**Considered and deferred**, with reasons:

- **OBJ + MTL sidecars** — `parseObj` ignores materials entirely. Porting needs a
  new backend endpoint serving files adjacent to the model, so it is a half-day,
  not an hour. Only 7 OBJ models in the library.
- **PNG snapshot / "set current view as thumbnail"** — trivial client-side
  (`renderer.domElement.toDataURL`), but the version worth having writes the
  result back as a custom thumbnail, which needs backend + schema work.
- **`applyCameraAction`** (keyboard orbit/pan/zoom) — clean and self-contained,
  but the detail panel already binds arrow keys to next/prev model.
- **`assertModelWithinBudget`** — weaker than what YASTL already does. YASTL
  gates on DB-known `face_count` and file size *before* fetching; NexoIP checks
  after parsing.
- **Electron main process, React components, animation playback** — not
  applicable. Print models are static.

## #CONN — YASTL Connect browser extension — 8 of 9 SHIPPED 2026-08-30 (branch `claude/connect-extension`)

**Plan:** `docs/plan-connect-extension.md` — full design, correlation strategy,
capture modes, security posture. Branch `claude/connect-extension`.

A Manifest V3 extension that captures model downloads from hosting sites and
pushes them into a library with the page's metadata attached. Written from
scratch — MeshVault Connect (the extension that prompted this) is closed-source
proprietary freeware and cannot be forked or bundled.

The point is what server-side URL import structurally cannot do: auth-walled
downloads, Cloudflare-gated sites, one-shot presigned CDN URLs, and gallery /
README capture. The browser is already authenticated; move the fetch there.

| Mnemonic | Subject | Status |
|---|---|---|
| CONN-1 | Server: `app/api/routes_connect.py` — `/info`, `/targets`, `/capture`, `/token`; token dependency; `connect_enabled` + `connect_token` settings | done |
| CONN-2 | Server: Settings -> Connect card (toggle, generate/regenerate/copy token, security note) | done |
| CONN-3 | Extension skeleton: MV3 manifest, service worker, YASTL API client, options page, icons | done |
| CONN-4 | Extension: content-script page harvester + per-site normalizers + `/api/import/preview` merge | done |
| CONN-5 | Extension: download interception, `referrer` correlation, Copy/Intercept capture modes | done |
| CONN-6 | Extension: popup — destination picker, capture queue, progress, retry, unattributed captures | done |
| CONN-7 | Gallery images + README bundling; needs `process_uploaded_zip` to stop discarding non-model entries so the docs viewer can see them | **remaining** |
| CONN-8 | Tests: 19 pytest cases for the connect routes, 20 Node cases for the normalizers, both wired into CI | done |
| CONN-9 | Docs: `extension/README.md`, CLAUDE.md architecture note | done |

**Verified live**, not only under test: a real STL posted over HTTP to a running
server landed at `<library>/connect/2026/cable_clip.stl` with its name,
description, `source_url`, `license`, tags (including `author:Jamie` as a
namespaced tag), extracted geometry and a generated thumbnail. Auth states check
out too — 403 while disabled, 401 on a wrong token, 401 for a token invalidated
by regeneration.

**The honest gap:** the extension has never run in a real browser against a real
model site. Everything mechanical is tested, but the per-site DOM selectors in
`content.js` and the download-correlation heuristics in `background.js` are
written against how those sites are documented to behave, not against how they
actually behaved on the day. That needs a manual pass — load unpacked, download
something from each of the six sites, fix what misses. Expect the selectors to
need adjusting; that is what the Open Graph and JSON-LD fallback layers are for.

CONN-7 is the only planned item left, and is genuinely optional.

## Reference — shipped this session (all on `main`, deployed to CT333 @ c30ca28)

See memory `meshory-feature-wave.md` for detail. In short:

- **Simplicity:** minimal grid density (3-way toggle), folder-first onboarding,
  local-first README framing.
- **Print pipeline:** filament inventory · finished-prints log + location
  inventory (with filament deduction) · print queue (queued→printing→done,
  auto-logs a print on completion).
- **Multi-plate Bambu 3MF:** zip-peek detection, card badge, detail plate strip
  (reuses embedded slicer previews), **per-plate 3D viewer selector**.
- **Slicer handoff:** OrcaSlicer/Cura one-click via URL scheme; Prusa/Bambu/
  SuperSlicer download fallback (their schemes whitelist printables/makerworld).
- **Optional AI (BYO-key, off by default):** Phase 0 provider plumbing →
  Phase 1 semantic/hybrid search (embeddings + RRF) → Phase 2 vision
  auto-tagging.
- Plus: 10 README screenshots (synthetic gallery), `formatDate` UTC fix.

Full backlog + implementation plans: `docs/ideas-meshory.md` (local, uncommitted).
